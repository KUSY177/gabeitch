# Документация разработчика проекта "gabeitch"

Данная документация описывает структуру проекта, модули, классы и игровые системы 2D‑платформера *gabeitch*.  
Проект разработан на Python с использованием библиотеки **Arcade** и имеет модульную архитектуру, обеспечивающую удобство сопровождения и расширения.

---

# 1. Структура проекта

gabeitch/

  main.py                 — точка входа в игру
  
  game.py                 — основной игровой цикл
  
  player.py               — класс игрока
  
  enemy.py                — класс врагов
  
  level_loader.py         — загрузка уровней из JSON
  
  constants.py            — глобальные константы проекта

  assets/
  
    sprites/              — спрайты персонажей и объектов
    
    tilesets/             — тайлсеты уровней
    
    sounds/               — звуковые эффекты
    

  levels/
  
    level1.json
    
    level2.json
    
    ...


Код

Каждый модуль выполняет строго определённую функцию и взаимодействует с другими компонентами через чётко определённые интерфейсы.

---

# 2. Описание модулей и классов

## 2.1 main.py

Главная точка входа в приложение.

**Назначение:**
- инициализация окна игры;
- запуск основного игрового класса `GameView`;
- настройка параметров экрана.

---

## 2.2 game.py

Содержит основной игровой класс.

### Класс `GameView(arcade.View)`

**Отвечает за:**
- игровой цикл (update, on_draw);
- обработку пользовательского ввода;
- управление состояниями игры (пауза, смерть, переход между уровнями);
- загрузку уровней через `LevelLoader`;
- обновление всех игровых объектов (игрок, враги, платформы).

**Основные методы:**
- `on_draw()` — рендеринг сцены;
- `on_update(delta_time)` — обновление логики;
- `on_key_press()` — обработка нажатий;
- `load_level(name)` — загрузка уровня.

---

## 2.3 player.py

### Класс `Player(arcade.Sprite)`

**Отвечает за:**
- движение персонажа;
- прыжки;
- анимации;
- обработку столкновений;
- взаимодействие с объектами уровня.

**Основные поля:**
- скорость движения;
- скорость прыжка;
- состояние (idle, run, jump, fall);
- текущая анимация.

**Основные методы:**
- `update()` — обновление состояния;
- `update_animation()` — переключение кадров;
- `jump()` — выполнение прыжка.

---

## 2.4 enemy.py

### Класс `Enemy(arcade.Sprite)`

**Отвечает за:**
- движение врагов по заданной траектории;
- обнаружение столкновений с игроком;
- нанесение урона;
- проигрывание анимаций.

**Основные методы:**
- `update()` — логика патрулирования;
- `reverse_direction()` — смена направления движения.

---

## 2.5 level_loader.py

### Класс `LevelLoader`

Модуль загрузки уровней, созданных в редакторе **Tiled**.

**Отвечает за:**
- чтение JSON‑файлов уровней;
- создание платформ, врагов, объектов;
- размещение игрока;
- загрузку тайлмапов и слоёв.

**Основные методы:**
- `load_level(path)` — загрузка уровня;
- `create_platforms()` — создание платформ;
- `create_enemies()` — создание врагов.

---

## 2.6 constants.py

Модуль глобальных констант.

**Содержит:**
- размеры окна;
- скорость игрока;
- параметры физики;
- пути к ассетам;
- настройки уровней.

Пример:

```python
SCREEN_WIDTH = 1280
SCREEN_HEIGHT = 720
PLAYER_SPEED = 5
GRAVITY = 1.0
```
3. Игровые системы
3.1 Система физики
Реализована средствами Arcade:

гравитация;

столкновения со стенами и платформами;

обработка прыжков;

корректировка позиции при коллизиях.

3.2 Система анимаций
Использует:

спрайт-листы;

автоматическое переключение кадров;

состояния персонажа (idle/run/jump/fall).

3.3 Система уровней
Уровни хранятся в формате JSON, экспортированном из Tiled.

Каждый уровень содержит:

платформы;

врагов;

объекты;

стартовую позицию игрока.

3.4 Система ввода
Обрабатывает:

движение влево/вправо;

прыжок;

паузу;

взаимодействие с объектами.

3.5 Система столкновений
Обеспечивает:

проверку контактов игрока с платформами;

определение удара по врагу;

получение урона;

активацию объектов.

4. Описание каталогов проекта
4.1 Каталог assets/
Содержит все ресурсы, используемые игрой.

assets/sprites/
Хранятся спрайты персонажей, врагов, объектов и анимаций.

Примеры:

player_idle.png — кадры анимации ожидания игрока

player_run.png — кадры бега

enemy_walk.png — анимация врага

coin.png — объект для сбора

assets/tilesets/
Тайлсеты, используемые редактором Tiled для построения уровней.

Примеры:

ground_tiles.png — земля, платформы

decor_tiles.png — декоративные элементы

assets/sounds/
Звуковые эффекты игры.

Примеры:

jump.wav — звук прыжка

hit.wav — получение урона

coin.wav — сбор предмета

4.2 Каталог levels/
Содержит уровни в формате JSON, экспортированные из редактора Tiled.

Каждый уровень включает:

описание тайловых слоёв;

координаты платформ;

расположение врагов;

стартовую позицию игрока;

объекты для взаимодействия.

Примеры:

level1.json — обучающий уровень

level2.json — уровень средней сложности

5. Архитектура проекта
Проект построен по принципу модульной архитектуры, где каждый компонент отвечает за строго определённую часть логики.

5.1 Основные подсистемы
1. Подсистема рендеринга
Отвечает за:

отрисовку спрайтов;

отображение уровней;

визуальные эффекты.

Реализована средствами:

arcade.Sprite

arcade.SpriteList

arcade.View

2. Подсистема физики
Включает:

гравитацию;

обработку столкновений;

корректировку положения объектов.

Использует встроенный физический движок Arcade:

arcade.PhysicsEnginePlatformer

3. Подсистема управления
Обрабатывает:

нажатия клавиш;

прыжки;

движение;

взаимодействие с объектами.

Реализована в методах:

on_key_press()

on_key_release()

on_update()

4. Подсистема загрузки уровней
Отвечает за:

чтение JSON‑файлов;

создание платформ;

размещение врагов;

загрузку тайлмапов.

Реализована в классе:

LevelLoader

5. Подсистема анимаций
Включает:

переключение кадров;

выбор анимации в зависимости от состояния;

синхронизацию движения и визуализации.

Реализована в методах:

Player.update_animation()

Enemy.update_animation()

7. Обработка ошибок и исключений
В проекте предусмотрены базовые механизмы обработки ошибок:

Ошибки загрузки уровня
Если JSON‑файл повреждён или отсутствует:

выводится сообщение в консоль;

игра не завершается аварийно;

загружается fallback‑сцена или пустой уровень.

Ошибки ассетов
Если отсутствует спрайт или звук:

используется заглушка (если предусмотрена);

выводится предупреждение.

Ошибки ввода
Нажатия клавиш вне игрового окна игнорируются.
